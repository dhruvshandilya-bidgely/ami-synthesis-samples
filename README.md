Synthetic Residential AMI Sample Release
========================================

This release accompanies the paper "Long-Horizon, Appliance-Conditioned Synthesis of Residential AMI Data via Conditional Diffusion" (IEEE PES ISGT Asia 2026). It contains a small set of synthetic residential smart-meter (AMI) samples generated by the conditional diffusion model described in the paper, alongside samples from the two baseline generators (conditional VAE and conditional GAN) for comparison. Samples are provided for two appliances: electric vehicle (EV) charging and pool pump (PP).

The underlying real AMI dataset is proprietary (anonymized household pilots under data agreements that preclude redistribution) and is NOT included. The trained model weights are also not released. This release is intended to illustrate the model's conditional generation and appliance-toggling behavior, not to reproduce the full training pipeline.

Data format
-----------

Each .npy file is a single 2-D array of shape (360, 96):
  - rows  (360) = consecutive days
  - cols  (96)  = quarter-hour intervals within a day (15-min resolution; 96 intervals = 24 hours)

All values are DENORMALIZED into real units (they are NOT the z-scored values used internally during training). Energy is clipped at 0 (no negative values).

For each model and each appliance (ev, pp):
  - appliance_off/NN.npy : energy grid generated with condition (EV=0, PP=0) and NULL EV sub-attributes.
  - appliance_on/NN.npy  : energy grid generated with the appliance present:
                             * ev/ : condition (EV=1, PP=0), with the EV sub-attribute values listed for sample NN in the CSV.
                             * pp/ : condition (EV=0, PP=1), with NULL EV sub-attributes (pool pump carries no EV sub-attributes).
  - temperature/NN.npy   : the ambient temperature context supplied to the generator for pair NN. Units: °F. This is real (measured) temperature used as a conditioning input, shared by the off and on samples of the pair. These temperature profiles are drawn from held-out households (the test/validation split) that were NOT seen during training, so the released samples are conditioned on unseen weather context.


How the samples are paired (counterfactual toggling)
----------------------------------------------------

Within a single model and appliance, sample NN's "off" and "on" grids form a counterfactual pair: they are generated from the SAME latent noise and the SAME temperature context, differing ONLY in the appliance condition (absent vs. present) and, for EV, the associated sub-attributes. This isolates the effect of the appliance condition on the generated load. This holds for all three models (diffusion, VAE, and GAN) and both appliances.

Across models, sample NN of a given appliance shares the same temperature context (and, for EV, the same sub-attribute condition), but NOT the same latent noise. The three generators operate in different latent spaces (the diffusion model's initial noise is a 360x96 field; the GAN uses a 256-dim latent vector; the VAE uses a convolutional latent), so a common noise seed is not meaningful across them. Only the conditioning is held fixed across models.

EV and PP samples use different temperature contexts: EV samples are conditioned on temperature profiles from EV-source households, PP samples on temperature profiles from pool-pump-source households (pool-pump load is strongly weather-driven, so PP-source contexts are the representative choice). All temperature contexts come from held-out households in the test/validation split, not from any household used to train the models.


Sub-attribute conditions (EV only)
----------------------------------

subattribute_conditions.csv records the conditioning used for every sample.
Columns:

  model          : diffusion | vae | gan
  appliance      : ev | pp
  sample_id      : 00 ... 19  (matches the .npy filename)
  amp_bucket     : charging amplitude bucket        (integer index)
  count_bucket   : charging frequency bucket        (integer index)
  avgdur_bucket  : average charge duration bucket    (integer index)
  ctype_bucket   : charger type bucket              (integer index)
  tou_bucket     : time-of-use bucket               (integer index)
  amp, count, avgdur, ctype, tou : human-readable labels for the above

Pool pump (pp) rows carry NULL for every sub-attribute (index 0 / "NULL"), because pool-pump generation does not use EV sub-attributes. Sub-attributes apply only to EV.

Bucket index 0 always means NULL / absent. Label vocabularies:
  amp / count / avgdur : {NULL, low, med, high}
  ctype                : {NULL, L1, L2}          (Level-1 / Level-2 charger)
  tou                  : {NULL, day, mixed, night}

The EV sub-attribute tuple for each sample is drawn from the empirical joint distribution of real EV-positive households, so the synthetic conditions reflect realistic combinations. The same 20 EV sub-attribute tuples are used across all three models (EV sample NN has the same condition in every model).


Generation settings
--------------------

  - Diffusion sampler: DDIM, deterministic (eta = 0), 250 steps.
  - Diffusion classifier-free guidance weight: 1.0 (the operating point adopted throughout the paper). Note: the qualitative figures in the paper use a higher guidance weight purely for visual legibility; these released samples use the utility-optimal w = 1.0.
  - "Off" samples are generated at guidance 1.0 with NULL sub-attributes for all
    models and both appliances.


Notes and limitations
----------------------

  - These are model outputs, not real measurements, and are provided for illustration only.
  - The VAE and GAN are baselines; per the paper, the diffusion model produces substantially higher-utility synthetic data. Differences in sample quality across the three models are expected and are the subject of the paper's evaluation.
  - No real household data, no training data, and no model weights are included in this release.
